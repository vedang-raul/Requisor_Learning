Release Notes

Alma 41 — version 1.2.2

What's new since version 1.2.1 (live on learning.requisor.io).

Version Replaces Release Commit Database Changes
1.2.2 1.2.1 · 3bd49c6 Pending Yes — adds org_type column to universities
In short: The platform now supports both universities and companies as first-class partner types. Super admins can designate any new or existing partner as a university or a company, with distinct icons and labels throughout the admin panel. The role previously called "University Admin" is simplified to "Admin" across all user-facing surfaces, making the label work naturally for both partner types.

New for super admins

Company / Organisation partner type Super Admin
  • When adding or editing a partner, super admins now choose between University and Company / Organisation via a type toggle in the form.
  • The choice is stored in a new org_type column (VARCHAR(20), default 'university') on the universities table — existing partners are unaffected.
  • Each partner in the list now shows a coloured badge — green for University, blue for Company — so the type is visible at a glance.
  • The logo placeholder icon switches to a briefcase for companies and a building for universities, both in the list and in the create/edit form.
  • Name field placeholders update to match the chosen type (e.g. "Acme Corporation" for a company, "Milwaukee School of Engineering" for a university).
  • The confirmation dialog when removing a partner uses the correct label ("Remove company" vs "Remove university") and refers to the partner's admin generically.
  • Success toasts and error messages throughout the panel use context-aware wording ("added as a company", "A partner with that name already exists").

New for admins

Admins can create courses Admin
  • Organisation admins can now create and manage courses directly from the Tutor Workspace, without needing a separate tutor account.
  • Courses created by an admin are automatically scoped to their organisation — no manual assignment needed.
  • The existing course creation API already permitted the admin role; this release confirms and documents that the full creation UI is accessible to admins.

Improvements for everyone

"Admin" replaces "University Admin" everywhere Everyone
  • All user-facing labels, messages, and UI strings that previously said "university admin" now say "Admin" — shorter, clearer, and correct for both universities and companies.
  • The admin panel heading reads "Admin Panel" (instead of "University Admin Panel").
  • The role dropdown in People & Roles shows "Admin" rather than "University admin".
  • Pending-approval and sign-up hint messages now refer to "the organisation's admin" rather than "university admin".
  • The error raised when a non-super-admin tries to promote someone to admin reads: "Only a super admin can make someone an admin."
  • The AI assistant's system prompt refers to org-level admins as "an ADMIN: they run one organisation".
  • The View As card and the theme editor description are updated to match.
